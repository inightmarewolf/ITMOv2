# Mini Shop — Фронтенд (Практика 8)

Клиентское веб-приложение для учебного сервиса **Mini Shop** (`practices/practice_06/lab/service.py`).

## Библиотека компонентов и дизайн-система
- **Material UI (`@mui/material` v6 + `@emotion/react` + `@emotion/styled` + `@mui/icons-material`)**
- Единые цвета, типографика, отступы и видимый индикатор фокуса (`:focus-visible`) настроены в [src/theme.ts](src/theme.ts).
- Макет всех состояний экрана и описание вклада AI: [../mockup.html](../mockup.html) и [../MOCKUP_AND_AI.md](../MOCKUP_AND_AI.md).

## Основной пользовательский сценарий
1. Покупатель входит в систему (`POST /login`, демо-аккаунты: `alice` / `learn-alice`, `bob` / `learn-bob`).
2. Загружаются каталог товаров (`GET /products`) и список заказов (`GET /orders`).
3. Пользователь выбирает товар и оформляет заказ (`POST /orders` с заголовком `X-Token`).
4. Новый заказ сразу появляется в списке заказов, и его детали можно открыть в модальном диалоге.

## Установка и запуск

### 1. Запуск бэкенда (Mini Shop)
Из каталога `practices/practice_06/lab`:
```bash
python service.py --port 8066
```

### 2. Запуск фронтенда
Из каталога `practices/practice_08/frontend`:
```bash
npm install
npm run dev
```
Фронтенд откроется на `http://localhost:5173`. Запросы `/api/*` автоматически проксируются на `http://127.0.0.1:8066` через `vite.config.ts`.

## Запуск клиентских тестов
```bash
npm test
```
Тесты (`Vitest` + `React Testing Library`) проверяют:
- валидацию обязательных полей и длины пароля;
- отображение ошибки `401 invalid credentials`;
- состояния загрузки, пустого списка заказов и ошибки сервера с кнопкой «Повторить»;
- защиту от повторной отправки при двойном клике во время ожидания ответа;
- полный пользовательский сценарий от входа до создания заказа и работы с диалогом деталей.
