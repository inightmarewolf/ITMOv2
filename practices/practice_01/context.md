## Context Pack для первого рабочего сценария (TO BE)

Context Pack описывает правила **будущего** AI-помощника, а не текущий ручной процесс.

### Факты и правила

- Помощник анализирует один PR и возвращает: краткое описание изменения, не больше трёх рисков, список проверок ([README.md](README.md), «Задача помощника»)
- Риск обязан содержать: файл, строку в **итоговом файле** (не номер строки самого diff-файла), описание и доказательство цитатой из diff ([README.md](README.md), «Примеры комментария»; урок [prompts.md](prompts.md) P1-02)
- Приоритет категорий рисков (если кандидатов больше трёх): 1) correctness / падения (KeyError, необработанные исключения), 2) безопасность входа, 3) устойчивость (размер/DoS) — только если видно в diff
- Решение всегда принимает человек. Помощник НЕ может approve, merge или менять код ([README.md](README.md))
- Учебный стек целевого сервиса: Python + FastAPI ([TRAINING_PR.diff](TRAINING_PR.diff): `from fastapi import FastAPI`)

### Формат входа и результата

- **Вход:** diff одного PR в формате unified diff
- **Результат:**
  1. Краткое описание изменения (1–2 предложения)
  2. Не больше трёх рисков: файл, строка, описание, доказательство из diff, воспроизводимая проверка
  3. Список проверок (команды или сценарии)
- **Формат риска (хороший пример):** см. ниже

### Ограничения и запрещённые действия

- Помощник НЕ может approve или merge PR
- Помощник НЕ может менять код и НЕ предлагает патчи — только находит проблемы и проверки
- Помощник НЕ даёт общие советы без файла и строки
- Помощник НЕ превышает лимит три риска
- Помощник НЕ выдумывает проблемы вне diff и НЕ путает номера строк diff-файла с номерами строк исходника
- Решение всегда принимает человек

### Хороший пример

```text
app/api.py:~10, create_review — обращение payload["diff"] вызывает KeyError,
если в теле запроса нет поля diff. Доказательство: return review_service.review(payload["diff"]).
Проверка: curl -X POST /api/reviews -H "Content-Type: application/json" -d '{}'
```

Источник: [README.md](README.md), «Примеры комментария»; номера строк — по [TRAINING_PR.diff](TRAINING_PR.diff) (`@@ -1,8 +1,17 @@` → строка с `payload["diff"]` ≈ 10).

### Плохой пример

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

Проблемы: нет файла и строки, нет доказательства из diff, нет конкретной проверки; похоже на «исправь код», что запрещено.

Источник: [README.md](README.md), «Примеры комментария»

### Что пока неизвестно

- Нужно ли явно ставить severity (critical / major / minor) в отчёте?
- Достаточны ли только воспроизводимые curl/сценарии, или обязательны ещё unit/integration в CI?
- Лимит размера diff для production (в учебных артефактах принят 1MB — [product_management.md](product_management.md), [adr.md](adr.md)) — подтверждён ли бизнесом вне учебного кейса?
