# Рефлексия — практика 4

## Что взяли

Notify Mini вместо большого сквозного проекта: фича A (валидация имени) и фича B (список подписчиков). Так быстрее проверить связку среды, чем тащить весь бэклог курса.

## Что помогло

Короткий `AGENTS.md` как навигатор + контракт в `docs/requirements.md`. Skill `notify-tests` фиксирует процедуру «сначала runner, потом выводы» — без него агент чаще врёт про зелёные тесты. Свой MCP `subscribe_name` полезнее Context7 на этом проекте: сразу виден контракт API на success и `empty name`.

## Что мешало

Презентация рассчитана на OpenCode 2.0.20, у меня 1.18 — формат hook/plugins другой, пришлось писать `tool.execute.after` под фактическую версию. Локальная 4B в OpenCode для skill/MCP не подходит: тупит на tools. Рабочий прогон среды — через VseLLM.

## Где вмешался сам

Выбрал границы A/B, написал runner `scripts/check.py`, зафиксировал evidence MCP/тестов, подогнал plugin под 1.18. Без ручной проверки `make selfcheck` нельзя было бы честно сказать, что ошибочный вход MCP обрабатывается.

## Вывод

Ценность не в числе подключений, а в том, что каждое закрывает шаг: правила → skill → доменный MCP → автопроверка после edit.
