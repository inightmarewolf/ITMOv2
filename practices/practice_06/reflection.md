# Рефлексия — ДЗ 6

Сначала читал сервис как обычный маленький API и сразу было видно много простых дыр. Можно было подсмотреть чужой профиль или чек, подставить роль в заголовке, прислать свою цену в заказе, открыть логи без входа, протащить опасный HTML через отзыв. Это классика веба, без всякой «магии» нейросетей.

Часть с AI-помощником это усилила: сервер мог выполнить почти любой JSON с командой — удаление, выгрузка данных, чужой файл. Даже если модель «не хотела» ничего плохого, слепое исполнение на сервере всё равно опасно. Поэтому чинил проверками в коде и закрепил отдельными тестами.

После фикса те же опасные действия проверял ещё раз: отказ, свой чек — ок, `make step6` прошёл. С моделями по безопасности пришлось отдельно и целиком объяснять, что это учебный стенд с тестовыми данными, иначе они отказывались помогать и видели в запросе «хакинг».

Вывод простой: для такой лабы важнее цепочка «нашёл → закрыл в сервисе → проверил снова», чем уговаривать нейросеть «взломать». LLM удобна, чтобы быстрее разобрать код, но доступ и опасные действия всё равно должны резаться на сервере.
