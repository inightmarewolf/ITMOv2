Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Решение, для которого нужны альтернативы: как приоритизировать риски в Context Pack, если кандидатов больше трёх
- Критерии выбора: согласованность с README (≤3 риска); проверяемость; польза для ревьюера; без выдуманных severity-шкал без источника

## Запрос

Нужно ограничить отчёт помощника тремя рисками. Предложи три альтернативы правила отбора, сравни по критериям и выбери одну для записи в Context Pack context.md.

## Варианты решения

| Альтернатива | Плюсы | Минусы | Оценка по критериям |
|---|---|---|---|
| A. Фиксированный порядок категорий: correctness → security входа → устойчивость | Прозрачно; бьётся с багами TRAINING_PR (KeyError, LLM errors) | DoS/размер может вытеснить логику, если плохо отранжировать | Высокая |
| B. Только security-риски | Узкий фокус | README не ограничивает security; пропустим KeyError | Низкая |
| C. Любые три «самые длинные» описания | Просто | Нет критерия качества; провоцирует воду | Низкая |

## Выбор

- Выбранная альтернатива: A
- Почему: совпадает с реальными находками P1-01/P1-02 и не противоречит лимиту ≤3 из README
- Как проверим: при ревью TRAINING_PR.diff в топ-3 попадают KeyError и отсутствие обработки LLM до «косметики»
